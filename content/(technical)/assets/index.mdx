Every asset type (**mod**, **world**, **avatar**) runs on the same pipeline:

**asset → release → file slot → bytes → status**

You reserve a slot, stream the bytes into it, and Nox analyzes, validates and completes the upload
on its own. The same routes then serve those files back to clients.

| Type | Endpoint |
|---|---|
| `mod` | `/api/mods` |
| `world` | `/api/worlds` |
| `avatar` | `/api/avatars` |

## Envelope & options

- Every response is wrapped: `{ data, request, time }` on success,
  `{ data: null, error: { code, message, status }, request, time }` on error.
- Add `?full=1` to expand `url` (`{ proxified, original }`) and the asset release preference
  (`{ auto, value }`).
- Uploads go through the `upload` provider (owner / contributor / admin). A repository can also be
  served **read-only** through the `github` provider — see the GitHub page.
